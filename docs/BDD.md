# BDD 自动化验收：从演义人物抉择到可复现的战斗状态

## 可执行契约

- 场景文件：`features/lore.feature`、`features/save_resume.feature`、`features/novel_provenance.feature`
- 运行器：`tests/bdd.rs`，执行单一、严格的 Given / When / Then / And / But 子集。不是完整通用 Gherkin 解析器；不支持 Scenario Outline、Examples、Rule、Background、标签和数据表。遇到不认识的步骤，必须失败，不能自动跳过。
- CI：`cargo test --test bdd -- --nocapture`，`cargo test --all-targets` 也会执行 BDD 验收。
- 辅助质量门：Rust 单元测试、Clippy `-D warnings`、Release 构建、终端进度持久化冒烟、两平台各 1000 局种子模拟。
- 内容审查：必须有小说回目 provenance；游戏虚构、小说演义、史实评价分开，不能写成已验证史实。

## 行为覆盖目录

| 验收域 | BDD 意图 | 反向场景 |
|---|---|---|
| 关羽：白马→华容 | 恩义结缘、之后有条件地出现回报、跨存档保留 | 只取赏金则后续不解锁 |
| 关羽：桃园 | 结义后开战实际增加护甲 | 不结誓不触发 |
| 诸葛亮：隆中→草船 | 历史关系门槛开启对应谋略线并增加开战谋略 | 未经历铺垫不会触发 |
| 孙尚香：联姻→截江 | 关系旗标连接吴蜀亲缘及连段起始资源 | 拒绝事件不获得 |
| 曹操：迁许→官渡 | 荀彧关系及统御初始加成 | 未见许都事件没有官渡后续 |
| 吕布：赤兔→凤仪 | 选择留下背盟痕迹，演变为怒气初始加成 | 省略铺垫不能跳到后续 |
| 彩蛋：白马旧债→华容 | 一条完整旗标链触发一次隐藏结局，读档状态不重复奖励 | 未集齐不得出现 |
| 强制拒绝错误动作 | 选项编号错误不可更改金币、人物结缘、RNG、修订号 | 非法选择必须被拒绝 |
| 回合中断恢复 | 战斗已开始、结束回合、序列化再读取仍处在有效场景 | 快照转换不能重排状态 |
| 小说章回 | 120回连续编号、各回有可追溯的经典文本索引 URL | 任意来源缺失、孤儿前置旗标失败 |
| 文学与史实 | 资料明确标识本项目并非正史复现及尚未完成逐回审校 | 不能把目录校核当作全文读校 |

## 测试编写约定

每新增一个三国故事，应有至少一对场景：玩家遵守诺言获得旗标的正向路径，以及放弃、交易或失败时不能凭空触发伏笔的反向路径。

每新增一个武将羁绊，应测试：

1. 实际生效的战斗资源变化，例如护甲或谋略，而不只测试文案；
2. 同一人物在不同宿命选择后，是否能/不能取得另一章节；
3. 战斗中或事件中中断后的 JSON 往返严格相同；
4. 已完成的隐藏彩蛋不能再次获得奖励；
5. `Game::apply` 失败指令必须完全回滚。

每新增一个来源章节，应核查 `data/novel_chapters.tsv` 中的准确回目和 `src/lore.rs` 的编号。**该 TSV 仅为120回目录，并不等同于已读完120回正文。** 人物关系和历史情节的逐回核对记录持续维护在 `NOVEL_STUDY.md`。

## 如何运行

```bash
cargo test --test bdd -- --nocapture
cargo test --all-targets
cargo run --release --bin tks-sim -- 1000
```

这里的 BDD 场景是业务行为测试，不代表完全覆盖全部卡牌组合、所有剧情线或所有战役随机状态。完整质量门还需要真正的状态机模型测试、所有事件分支的穷举、组合机制边界与回放日志。
