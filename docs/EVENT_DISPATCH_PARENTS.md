# 同步战斗事件父子关系（2026-10-25，待双平台 CI）

本次从超过 5200 行的 `src/lib.rs` 抽出原有战斗事件派发代码到 `src/combat_dispatch.rs`，保留原本事件顺序与全部游戏效果。在原有派发入口维护**仅用于诊断**的同步调用上下文：如果事件 B 是处理事件 A 的观察者（observer）期间产生，B 记录 A 的 `encounter/seq` 为父事件；A 派发返回后恢复此前上下文。没有同步父事件时为 `null`，不按“时间最近”猜测。

`Game::reconstruct_event_dispatch_parents()` 从种子和已提交动作重放，检查每个前缀、完整事件档案、最终 Game 快照和父坐标先后顺序；`tks-attest save.json --event-parents` 只读输出 JSON。诊断上下文用 `serde(skip)`，不写入 V2 存档，不改变游戏规则、RNG 或事件序列。已有旧存档若缺少完整动作/事件档案则拒绝提供虚假父链。

验证：Rust 单元测试构造 `CardDrawn → WisdomOnDraw PowerTriggered` 两组真实同步父子链，确保下一次顶层抽牌不会错误继承上次父事件；集成测试覆盖五职业 × 0/10 飞升 × 重启后的真实动作回放、档案/动作/快照篡改拒绝；跨进程 `checkpoint_cli_e2e.py` 校验 JSON 父链、事件顺序和保存文件只读不变。以 PR 最终 HEAD 的 macOS/Linux Rust、CLI E2E 与跨平台确定性 CI 为准。

**可信边界：** 这是执行调用栈直接观察的父子关系，仅涵盖战斗事件派发期间同步产生的子事件。独立顺序执行的卡牌效果、先于事件发生的 RNG 抽样、延迟效果和不同动作间的关联不能因此认定为父子；不提供外部签名或独立事件归约完整 Game 的能力。外部可信检查点仍需单独保存。P1 事件源、15 套成熟构筑、全效果交互与 120 回正文审校均未完成，不发布 1.0。
