# 三国登塔录：平衡测试方法与边界

## 背景与核心问题

在 2026-10-16 原始主分支 1000 局简单机器人 CI 中，胜利 228 局（22.8%），但是该数值仅来自“第一张可打的牌→永远打第一个存活敌人→奖励永远选1→不主动用药剂”的简单机器人。**不是玩家通关率，也不能直接用来削弱某位武将。**

本轮基于可重放引擎增加了成对策略对照与分层机器报告。目的是识别**自动化策略明显失衡、部分难度无法通关、职业/种子是否偏斜，以及哪类遭遇战更容易让测试机器人失败**，不是替代真人试玩。

## 两种策略

- `first_playable_baseline`：沿用历史 CI 的最简单策略，保持作为回归基准。地图/奖励选1；战斗优先打出第一张可支付费用的牌；敌军优先选第一个存活者；不主动使用药剂。
- `tactical_heuristic`：按法术效果、能耗、卡牌升级情况与可预告敌军伤害粗略选牌；优先攻击生命加护甲更低的存活敌人，低血量时自动使用回复药剂、低军令时尝试军令药剂；战利品根据卡牌效果与重复卡惩罚选择；根据生命状态选择营寨休整/升级，金币足够时优先购遗物，演义有因果时选结缘。该策略**仅是可解释的规则机器人，不是优化后的 AI 或训练模型**。

双方在同一武将、飞升难度与种子下配对对局。但由于双方路由和选择不同，后续遭遇内容可能不同，不能把胜率差异直接解读为某个卡牌/技能的净因果效应。

## 数据粒度与样本

运行：

```bash
cargo run --release --bin tks-sim -- --balance 20 ./balance.json
```

- 五名武将 × 飞升 0–10 共 **55 个分层单元**。
- 每个单元 **20 个独立种子**，两个策略在对应种子上各运行一局；总计 **2200 局**，单策略 1100 局。
- 报告以 **策略 × 武将 × 飞升** 为比较单位，字段包含胜场、样本数、累积抵达层数、关底遭遇失败次数，以及失败时所在敌军阵容的描述。
- 按 0–3、4–7、8–10 飞升层级聚合展示，分别是每职业 80、80、60 局/策略；不得把单个 20 样本单元当作高置信度的难度定论。
- `death_encounter` 表示失败**所在战斗的敌军阵容**，不是最后一击的实际来源。战败前最后一幕不在战斗时标记 `non-combat`。
- 固定种子的分层编号公式写入 JSON 的 `seed_formula`；每个平台输出 `tks-balance.json`，由 GitHub Actions 保存供复查。报告没有遥测个人玩家操作。

## 验收

- 确保 55 个独立样本单元各有 20 条配对输入，合计两策略各 1100 局。
- 两份失败遭遇的总次数必须分别等于 `1100 - 对应策略胜场数`。
- `Game::apply` 仍保证失败操作完全回滚；每局定期跨 JSON 快照恢复并验证字节级状态一致。
- 独立种子的可重复模拟单元测试校验相同策略、武将、种子和难度输出相同快照。
- 不设“策略胜率必须提升”或“某武将必须达到既定胜率”的脆弱质量门：数据用于发现问题，而不是操纵测试使其只呈现好结果。

## 决策原则

优先修复破坏性错误（软锁、负值、重复结算、不能存档）和明显卡牌强度异常；再根据多个策略和足量样本观察不同飞升下的差异。**缺少人类玩家分布与逐卡选择日志时，仅能提出暂定平衡建议，不应贸然全局改动 Boss 血量、所有职业起始生命等高影响参数。**
