# P1 四类权威日志逐修订一致性审计（2026-10-24）

资源、战斗军令/护甲、敌军棋盘、卡牌区域分别具备独立归约器，但单独检查最终快照无法发现中途互相矛盾的记录。例如：敌军日志第1次行动声称进入第2回合，卡牌与军令日志仍处第1回合，随后三者又恢复一致。此前各自的最终审计可能都通过。

新增只读 `Game::audit_authority_bundle()`，按每次成功动作的全局修订号同步推进四个已有归约器。要求：

- 四份日志均有起点、长度均为 `Game.revision + 1`，每份修订号从0连续至当前版本；旧V2缺任何一份时明确拒绝审计，不生成历史。
- **每一个**修订边界，战斗军令、敌军棋盘、卡牌区域必须同时处于战斗或非战斗；处于战斗时，楼层与回合必须一致。发现中途分歧立即拒绝，即使最终快照又恢复一致。
- 最终从事件独立恢复的生命、最大生命、金币、军令、护甲、敌军及有序牌区，必须与当前 `Game` 一致。无需重放动作、读取RNG或执行战斗规则。
- 审计不修改游戏或事件日志，不改变V2存档结构。原子动作仍由原有 `Game::apply` 提交；本接口仅用于显式审计，避免每次动作重放全部历史。

## 复验

```bash
cargo test --test authority_bundle
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

Rust回归包括合法游戏、序列化往返、缺失与截断日志、失败动作原子性，以及**单份日志终态合法、但中途回合与其它日志矛盾**的两类伪造。

**2026-10-24 原四日志未验收边界：**当时尚未记录持续军略和动态监听器；四类日志仅包含动作提交后的部分状态，不含完整RNG、所有奖励/地图/剧情状态及动作内部触发链。同步篡改多份日志与快照仍可能逃过校验；本接口不是密码学认证、可信检查点或完整Game事件源重建。构筑成熟度、全道具/敌军组合、120回正文及异本校勘、真人试玩、国际化仍未完成，不发布1.0。

## 2026-10-25 五日志扩展

新增战斗持续军略/动态监听器动作边界日志 `combat_effect_history`，审计同步检查五份日志的修订号、战斗进入/退出、楼层与回合，并对照最终军略层数及监听器状态。旧V2缺第五日志仍可读档和动作重放，但五日志审计明确拒绝，绝不自动补造历史。详情见 [战斗效果权威日志](COMBAT_EFFECT_AUTHORITY.md)。动作内逐次触发、事件替换、RNG及可信事件链仍未覆盖。

## 2026-10-25 单修订边界的统一投影视图

新增只读 `Game::project_authority_boundary(revision)`：先验证五份日志的**完整历史**，再仅用事件归约器恢复指定修订边界的资源、战斗军令与护甲、敌军棋盘、永久/战斗卡牌区域、持续军略和动态监听器，返回可序列化 JSON 视图。修订号0可查询；超出当前版本拒绝；即使只请求旧边界，尾部日志缺失或跨日志冲突也必须拒绝，不将有问题的前缀冒充已认证状态。旧V2缺日志继续拒绝审计。

```bash
cargo test --test authority_bundle
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

这是**五类已覆盖状态的部分投影**，不包含 RNG、地图、奖励、道具、剧情、战功、动作内因果触发等完整 Game 状态，也不验证协调篡改或外部可信锚点。查询会从头归约日志且先执行全历史审计，属于离线审计接口，不能放入逐帧 UI 或每次动作热路径。新增回归验证修订0、战斗进入、回合推进、存档往返、脱离动作日志、尾部缺失和越界拒绝；仍不得宣称完整事件源重建或 P1 验收完成。
