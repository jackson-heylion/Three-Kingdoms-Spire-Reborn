# P1：完整 Game 历史版本重建（动作重放，非独立事件源）

`Game::reconstruct_game_at(revision)` 从固定种子、武将、模式及完整成功动作日志重新执行游戏规则，返回指定修订号的**完整 Game**，而不是六类局部权威日志的投影。结果包括地图、路线、战斗、RNG、牌组与背包、奖励、军市、持续军略、动态监听器、剧情旗标及现有审计日志。调用不修改当前游戏；`revision=0` 返回开局状态，`revision=self.revision` 返回最终动作重建状态。

- 严格要求完整 `action_history` 且长度等于当前 `revision`；超出范围、缺失日志或非法动作均拒绝重建。
- `verify_action_replay()` 现在复用同一重建路径，并比较最终 **Game 全字段 JSON**，包括六类日志与跨幕剧情；只重建历史前缀不能证明原始日志没有被删除或重写。
- 旧 V2 缺失某类日志时，重建结果继续保持 `None`，不把未记录的历史伪装成已审计事件。
- 外部战功簿是另一个文件，不属于 Game 动作日志；重建保留已有 `profile_start_receipt`，不重写战功簿。

## 证据与边界

`tests/game_revision_reconstruction.rs` 对五职业 × 飞升 0/10 的十条真实规则路径分别执行战法选择、地图进入战斗、敌方回合，逐版本对比完整序列化状态；另外覆盖旧档日志缺失、截断、伪造动作、未来修订号及当前快照篡改。由原有 macOS/Ubuntu Rust CI 执行；须以 PR 最终 SHA 的实际检查结果为准。

这是**确定性动作重放（deterministic action replay）**，不是独立可信的**事件源（event sourcing）**：日志与快照同存、未签名，不能抵御有意同时篡改动作日志与快照；历史中每个随机抽样的因果、独立可信检查点、全量事件归约与版本升级后的规则兼容仍未解决。重放成本随历史动作数增长，仅用于离线核查/诊断，不应直接作为每帧 TUI 渲染或在线行动的热路径。真人试玩、15套构筑成熟度、120回正文与异本史料审校均未因此验收。
