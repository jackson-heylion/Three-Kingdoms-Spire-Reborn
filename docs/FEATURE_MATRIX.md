## 验收缺口与发布定义

**“完整单人终端版”**：上表除了多人/UI2期外均须达到“完整且经测试”；具体卡牌和事件全部来自本项目原创新设定，而非假称原作的成套内容复刻。完成前版号维持 `0.x alpha`。

**“全部游戏玩法”**：若参照当前《杀戮尖塔 2》公开功能，还必须包含多人合作、更多角色资源、完整成长解锁、故事路径、古老存在奖励、各类卡牌关键词、状态效果和定制模式，故当前 P0 并不符合此描述。游戏仍处抢先体验，功能总量与行为可能持续变化。

## 提高内容深度的工程原则

1. 首先定义机制行为和事件顺序，再为其填充原创卡牌和遗物数据；
2. 每个职业至少要有可独立通关的数种牌组方向以及克制对象，而不是只有签名卡和不同 HP；
3. 每张卡应有稳定 ID / 费用 / 升级变化 / 触发点 / 目标模式 / 状态副作用 / 存档策略；
4. 任何改动都必须能通过 `Game::apply(Action)` 从快照重演，便于未来三前端和多人服务共享；
5. 不将主观体验近似量化为官方内容覆盖百分比。

## 文学章回内容要求

新增剧情需要关联 `data/novel_chapters.tsv` 中的 1–120 回来源，明确演义/正史区别，并在 `features/*.feature` 验证前置条件、选择后果、角色羁绊、隐藏结局及跨存档一致性。目录索引已建立不等于逐字读完正文，全部人物事件整合仍在开发。

## 战斗事件追踪

`src/combat.rs` 定义的16类事件为 `CardPlayed`、`CardResolved`、`CardDiscarded`、`CardDrawn`、`CardExhausted`、`DamageDealt`、`DamageReceived`、`StatusApplied`、`FoeDefeated`、`PowerGained`、`PowerTriggered`、`TurnEnded`、`TurnStarted`。事件簿保留最近80项，序号单调递增，持久化进入V2快照。敌人仅在 HP 首次降为零时触发一次死亡事件，中毒追加不递归再发中毒事件；“抽牌”只在抽牌成功时发事件。此系统具备集中确定性派发和本轮触发注册表的语义，但**不是**任意插件可注册的事件栈、完整事件重放或原作全机制。
