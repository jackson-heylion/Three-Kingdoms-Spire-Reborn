# P1：成功动作与战斗事件的可重演因果归属

`Game::reconstruct_action_event_trace()` 从初始战役和成功动作逐步重演真实规则，将全战役 `event_history` 按每次 `Game::apply` 的提交边界分组。每组提供动作、修订号、动作前后阶段、RNG 状态以及按原顺序发出的全部战斗事件（含嵌套监听、替换、反制产生的事件）。

**验证约束**：动作日志必须完整且修订号一致；每一步新产生的事件必须与保存的事件档案对应位置逐条相等；所有事件必须归属于某一步成功动作；最终完整 Game 必须与存档一致。缺失旧版事件档案时明确拒绝，不伪造事件证据。只读运行，不改变存档、随机状态或事件序号。

`tests/action_event_causality.rs` 覆盖五职业×飞升0/10的十条真实规则路径，并检查事件顺序、RNG 边界连续、跨进程序列化恢复、只读性质、档案篡改/截断、快照篡改和旧档缺失。由现有 macOS/Ubuntu Rust CI 执行，以 PR 最终 SHA 的实际结果为准。

**不能宣称完整事件源**：本接口建立的是「动作→事件」归属，未建立每次 RNG 抽样的调用点与抽样值、事件内部父子触发关系、独立事件归约重建整个 Game、可信外部锚点或跨版本规则迁移。动作日志与事件档案仍同存且未签名，攻击者可同时伪造两者及快照。重放成本随动作/历史增长，不应在 TUI 每帧执行。完整 P1、真人试玩、15套成熟构筑及120回异本史料校勘仍未验收。
