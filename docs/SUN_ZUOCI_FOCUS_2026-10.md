## 本轮实验

在 `tests/boss_build_duels.rs` 中新增显式执行的 `sun_zuoci_independent_seed_pairs`：

- 孙尚香的 `sun_discard`、`sun_combo`、`sun_poison`，统一对左慈。
- 飞升0与10各16个**新的**固定种子，共32个不同的「飞升×种子」条件；三套构筑共用这32组条件。每个条件只执行一次原始牌组基线，再分别执行三套预设构筑，共**96组配对、128场真实战斗**。
- 仍使用首层120血单体Boss合成夹具、人工替换6张卡和 `first_playable` 机器人；原有战斗行动、事件计数与V2存档往返测试不变。
- 逐组导出胜负、英雄承伤、Boss二阶段、特殊技事件和动作数。CI拒绝重复种子、缺失构筑、类型错误、跨构筑基线不一致，并分别打印各构筑×飞升的配对胜负、精确McNemar双侧p值与总承伤。
- macOS 14和Ubuntu分别执行、上传 `tks-sun-zuoci.json`，CI逐字节比较报告。原120组报告保持不变，禁止混合统计口径。

复验：

```bash
TKS_SUN_ZUOCI_REPORT=/tmp/tks-sun-zuoci.json cargo test --test boss_build_duels sun_zuoci_independent_seed_pairs -- --ignored --nocapture
```

## 解释边界

32组条件是32个**不同伪随机种子**，不是96个独立基线，也不是随机抽样的真人战斗。三套构筑共用相同基线，跨构筑统计存在相关性；每构筑32对、每飞升16对，仍不足以确认稳定优势或Boss特异因果克制。共用初始种子也不保证不同出牌路径中后续RNG同步。承伤为审计事件累计的毛伤害，不等于净生命变化。

若复验仍显示弃换弱势，应先对失败局的牌序、弃换触发、回合军令与左慈回复进行事件级归因，再尝试最小规则修复；不得仅凭胜率差直接调参。未完成自然构筑、全Boss、多策略、真人试玩、120回全文异本史料校勘、完整国际化和正式1.0验收。
