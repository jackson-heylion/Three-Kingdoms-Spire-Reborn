# 十种战法流派：由正常战役奖励自然成型

**截至 2026-10-16**：已经完成第一版可选流派引导。它不直接赠牌，不把测试用的预设构筑混入正常战役，也不代表职业流派的全部深度已经完成。

## 两条原创构筑路线／武将

| 武将 | 流派1 | 流派2 |
| --- | --- | --- |
| 关羽 | `guan_charge` 单骑破阵（战意/输出） | `guan_oath` 桃园义阵（义阵/防御） |
| 诸葛亮 | `zhuge_scheme` 八卦奇谋（谋略） | `zhuge_wisdom` 观星奇策（抽牌/调度） |
| 孙尚香 | `sun_discard` 飞羽换阵（主动弃换） | `sun_combo` 连弩追击（连续攻击） |
| 曹操 | `cao_troops` 虎豹亲军（亲兵/护卫） | `cao_command` 魏武号令（统御/资源） |
| 吕布 | `lu_fury` 无双怒袭（怒气爆发） | `lu_blood` 浴血战魂（自损/续航） |

实际卡牌映射在 `src/archetypes.rs` 维护。十个流派均按稳定卡牌ID匹配，每张专属卡都归属所属武将的一条路线，含流派名称、所属英雄和具体候选池。

## 在 macOS 终端使用

```text
new sun 9011
doctrine                # 查看当前武将的两条流派及自动识别状态
doctrine sun_discard    # 主动偏向主动弃换流派
choose 1                # 沿正常地图开始冒险
doctrine sun_combo      # 仅在地图或营寨可切换；战斗中被拒绝
doctrine auto           # 恢复由实际已获得卡牌自动识别
```

**规则透明度**：

1. 初始模式是 `auto`，没有预设卡组，也没有强行指定孙尚香应该走弃换或连段。
2. 玩家主动选择一条合法的本武将流派后，后续奖励页先按原随机规则生成3张互不重复的牌。若其中已有契合卡，整页保持不变；否则以 **70%概率** 选择1张尚未拥有、属于此流派的卡牌替换原随机牌中的1张。**至少保留其他2个随机选项**，且仍可以跳过奖励。军市是独立随机商店，不参与这种战后奖励引导。
3. 不主动选择时，只有实际战役牌组里已经拥有同一流派 **2张不同的专属卡** 且另一条路线的不同卡数量更少，才从当下开始自动识别。重复得到同一种卡不能冒充流派成型；两条流派证据数量相同则保持中立。
4. `Game::apply(Action::SetDoctrine)` 只允许在地图或营寨操作。跨武将流派、不存在的代码、战斗中/战后奖励页更换都会整体事务回滚，不得利用切换强迫刷新已展示的奖励。
5. `Game.doctrine: Option<Doctrine>` 用稳定英文代码序列化到V2快照，默认 `None` 且未选择时序列化省略，既有存档按之前的随机规则运作，直到形成可自动识别的自然构筑或玩家主动设定偏好。

## 使用正常10张起始牌组的分层实验

来源：[完成的 macOS/Linux 双平台 CI](https://github.com/jackson-heylion/Three-Kingdoms-Spire-Reborn/actions/runs/38860643280)。运行 `cargo run --release --bin tks-sim -- --natural-drafting 15 natural.json`。

实验采用**孙尚香正常10张起始牌组**，不提前注入流派卡：11级飞升×15独立种子×3种选择政策，共 **495局**。三种政策是同一套战术机器人，只改变玩家在地图出征前是否主动设定 `sun_discard` / `sun_combo`，以及由此产生的奖励权重与机器人对相应奖励的评分。所有三组使用相同种子集合，但后续卡牌和路线会因选择差异而分叉。统计“成型”定义为战役结束时拥有对应流派至少2种不同专属卡，不代表满足全部完整构筑组件。

| 分组 | 飞升8–10胜场（45局） | 弃换流派成型 | 连段流派成型 | 契合选项页／战后奖励页 |
| --- | ---: | ---: | ---: | ---: |
| 未指定／自动识别 | 34/45（75.6%） | 29/45 | 41/45 | 91/198 |
| 主动偏向弃换 | 37/45（82.2%） | **45/45** | 21/45 | **165/202** |
| 主动偏向连段 | 34/45（75.6%） | 9/45 | **45/45** | **169/184** |

观察：**定向引导显著提高了玩家选择的流派在测试局里的卡牌多样性和实际出现机会**。但“流派成型”只按2种卡的最低判据衡量，且主动选连段并未在这些高飞升种子上提高通关率；不应称已完成流派平衡或所有打法都有正收益。

对照上一轮 `--sun-archetypes` 测试时人为替换4张起始牌的495局不同，新测试衡量的是**从真实正常起始牌组及自然奖励逐步获取职业牌**，更接近普通战役，但仍没有真人选择或流派强度因果识别。

## 长回合防死循环：粮尽

平衡模拟中发现，左慈可重复回血而诸葛亮牌组也可能长期完美防御，在个别种子里**709回合仍不决胜**。为避免无无限界的游戏战役僵局，战斗回合数 **35–39** 在终端显示“持久战粮尽倒计时”，**第40回合起** 每完整结束一回合施加穿透护甲的粮尽生命损失，初始1，每4回合增加1。此事件以 `DamageReceived` 类型、`supply_exhaustion` 来源记录。达到0生命按战败结算，保留计数和完整回合快照。39回合及以内无此效果。机制具体数值尚待玩家体验验证。

## 验收范围

- `src/archetypes.rs` 测试10条流派 ID、专属卡所属、不能重复卡计数等；
- 引擎 Rust 单测核验：没有偏好时随机数序列与旧规则一致，奖励必须三张不同牌、不凭空改变永久卡组，跨武将/奖励页面非法操作回滚，旧版存档兼容，粮尽无视护甲且可能致死；
- `features/doctrine_drafting.feature` 5个BDD验收，包括正常击败敌人后看到三张合法战利品、存档恢复后选卡不变；
- GitHub macOS/Linux CI 总共53条BDD，1000局基础、2200局双策略、495局预设等量构筑、495局自然成型实验，每平台共4190局自动对局（各实验策略样本可能重叠）；三个 JSON 报告分别执行跨OS逐字节一致性校验，终端CLI `doctrine` 命令及二次启动恢复都有冒烟测试。

## 后续真实缺口

十条流派目前提供明确卡池归属与柔性奖励引导，而**非**十套已验证独立通关的成熟套牌。还需测不同奖励稀有度、卡牌移除、路线/军市构筑选择、流派切换成本、人类测试及每种职业/流派跨难度胜率。本轮没有拷贝任何其他游戏的专有卡牌、故事或美术。
