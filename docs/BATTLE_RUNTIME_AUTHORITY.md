# P1：九域权威归约与完整战斗快照恢复

八域归约此前覆盖战役、资源、RNG、敌军、牌堆、持续军略、动态监听和统计，但未持久化战斗内的怒气、战意、谋略、亲兵、弃牌令、出牌计数、临时回合标志、事件序号与最近事件窗口。仅修改这些字段的合法 V2 快照可以绕过八域比对。

新增 `src/battle_runtime_events.rs` 作为第九条逐动作权威日志，保存其余全部 Battle 字段。新开局 revision 0 为 `Started`，成功动作在同一事务提交 `Enter/Update/Unchanged/Exit/Idle`；失败动作不写日志。每次归约要求修订号连续、同一场战斗楼层/回合不倒退、事件窗口序号连续，并与其他八域逐版本核对。

`AuthorityView::rebuild_battle()` 直接从九域状态重建完整 `Battle`，无需执行任何 Action、重新抽 RNG 或读取 Game 的可变 `battle` 字段。它只恢复**当前动作边界的战斗快照**，不是战斗事件逐条驱动的状态机，也不能恢复整个 `Game`（例如用户日志与战功簿）。

验证：`tests/battle_runtime_authority.rs` 覆盖五武将×双难度的战斗、存档恢复、九域重建逐字段一致、单独篡改怒气、独立合法但跨域矛盾的中间回合、失败步骤的原子回退，以及旧 V2 缺少第九域时可继续但不得认证。`tests/authority_cli_e2e.py` 在 macOS/Linux 真实进程审计中检查新域及篡改拒绝。以 PR 最终 SHA 的 Rust、BDD、CLI E2E 和跨平台确定性 CI 为准；本地无 Cargo 时不声称本地编译成功。

可信边界：九域与 Game 快照同处可修改的存档中，**不能抵御同时改写所有日志**；只有独立可信存储的 SHA-256 检查点才可提供额外锚定。旧 V2 无第九域仍可读取、继续与动作重放，但不得标记九域完整恢复。P1 完整 Game 事件源、15套成熟构筑、全交互矩阵、120回校勘、真人试玩与正式1.0均未验收。
