# P1：四位此前缺席的 Boss × 15 构筑 × 三种决策策略

本测试补齐旧版 `tests/boss_build_duels.rs` 仅覆盖司马懿、左慈的固定对位缺口，新增张角、董卓、孙坚、袁绍。所有样本使用实际 `Game::apply` 战斗结算、完整事件记录及定期 V2 存档往返。

## 可复验样本

- 15 套声明构筑 × 4 Boss × 飞升 0/10 × 3 种策略 × 1 固定种子 = **360 组同种子基线/构筑配对**，即 720 次战斗。种子公式为 `26_400_000 + plan_index*1000 + boss_index*100 + ascension`；同一组的三种策略复用种子。
- `first_playable`：按手牌顺序使用可打出的牌；`discard_aware`：有弃牌令时优先弃飞矢或诅咒；`guard_first`：敌人当前意图有攻击时优先打可负担的护甲牌，其余遵循第一策略。后两种不保证每场都产生不同动作。
- 对每组记录双方是否存活、受到的实际生命伤害、二阶段出现与否、Boss 专属战技次数、动作数、弃牌次数；统计配对胜负分歧，而非用不同种子直接相减。
- 无需额外命令，`cargo test --test boss_build_duels` 即运行本矩阵及原有测试。可选 `TKS_REMAINING_BOSS_DUEL_REPORT=/tmp/four-bosses.json cargo test --test boss_build_duels remaining_four_bosses -- --nocapture` 导出完整 JSON；GitHub Actions 的 Rust Tests 在 Ubuntu/macOS 都运行本测试，必须核对最终 HEAD。

## 不得越界解释

该试验强行将六张核心/辅助牌替换进十张起始牌组，且将单一 Boss 注入第一层、生命固定120；**不是**正常战役自然获得率、真实关底阵容、三幕全局路线、真人胜率或15套成熟构筑验收。三个策略仅为确定性启发式，不能当成三类真人水平。单种子、双难度用于发现规则与对位缺口，不足以形成可靠胜率估计。

原有司马懿、左慈对位和孙尚香/左慈多种子专项仍由旧测试独立覆盖。后续应将此处暴露的弱点带回正常战役的多种子、多路线、多策略实验，并针对具体 Boss 机制补回归；不得只以「六 Boss 均跑过」宣布平衡完成。
