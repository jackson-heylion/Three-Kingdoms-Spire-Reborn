# 战役级实测战斗统计与孙尚香流派对照

## 目标与范围

本轮继续处理 [首轮平衡报告](BALANCE_FINDINGS_2026-10-16.md) 的两个未决问题：**曹操亲兵和统御究竟贡献多少数值**、**孙尚香标准牌组、弃换流派与连段流派是否表现一致**。这是一项可重放的程序统计实验，不是玩家真实胜率调查。

## 核心引擎数据

`Game.telemetry: CombatTelemetry` 是**战役生命周期**指标，`#[serde(default)]` 兼容既有 V2 存档。实际计数使用 u64、饱和求和；存档快照仍由 `Game::apply` 进行事务校验。

| `CombatCounters` 字段 | 定义 |
| --- | --- |
| `troop_attacks` | 亲兵主动攻击结算次数，含打到护甲或实际伤害为0的情况 |
| `troop_damage` | 亲兵攻击实际减少敌方 HP 的伤害，**不含被护甲挡下的名义输出** |
| `troop_absorbed` | 敌方攻击先扣除英雄护甲后，真正被存活亲兵承担的伤害 |
| `command_procs` / `command_energy` / `command_block` | 曹操统御满3层触发次数，以及由触发提供的真实额外军令和格挡；不包含初始军令或卡牌独立收益 |
| `sun_discards` / `sun_discard_block` | 孙尚香合法主动弃换次数、因此直接获得的护甲；无可用弃换次数的非法操作不计入 |
| `sun_combo_procs` / `sun_combo_block` / `sun_combo_draws` | 每第三次攻击触发次数、产生的护甲、**实际成功进入手牌**的额外抽牌；手牌已满或牌库无牌时不虚增 |
| `hero_hp_damage` | 敌人通过防御及亲兵保护后，真正扣除英雄生命的伤害；不代表包含事件/卡牌自损在内的全部 HP 变化 |
| `battles_started` / `battles_won` / `battles_lost` | 遭遇战开始、胜利及**战斗中**失败的次数；非战斗事件失去生命不计为战斗失败 |
| `turns_completed` / `cards_played` | 发生完整回合结算的数量，以及玩家实际打出的牌数 |

`recent_turns` 保存最近 **24 个回合**（含胜利前提前结束的未完成回合）。每项含所处楼层、回合编号、回合是否完整结算、回合结束生命、亲兵生命和增量计数。旧回合记录会被淘汰，但 `totals` **始终累计整个战役**；这一诊断追踪不是事件溯源全量审计。

终端使用：

```text
metrics              # 查看累计的实际亲兵贡献、统御返还能量、孙尚香流派触发和最近8个回合
events               # 查看最近的强类型战斗事件，和 metrics 互相印证
```

## CI 的分层统计

`cargo run --release --bin tks-sim -- --balance 20 balance.json` 的 **55 个职业×飞升单元**每项增加 `baseline_telemetry` 和 `tactical_telemetry`。两个政策在同一种子条件下模拟，总共2200局，每个策略的计数在单元内严格求和。可以按 `troop_damage / turns_completed`、`troop_absorbed / turns_completed`、`command_energy / turns_completed` 理解样本平均每完整结算回合的指标；分母排除未完成回合，因此这些是诊断性近似而非严格时间加权速率。

## 孙尚香流派（隔离构筑实验）

使用：

```bash
cargo run --release --bin tks-sim -- --sun-archetypes 15 sun-archetypes.json
```

- 固定测试对象孙尚香、飞升 0–10、每难度15种子、三个相同种子组：合计 **495 局**，每流派165局。
- 三套牌组 **总张数完全一致**。标准组使用正常新战役初始牌组；另外两组统一移除两张基础突刺与两张基础招架，换入**4张**原创职业卡。此替换只存在于模拟器生成的测试战役中，**不会影响普通游戏模式的开局牌组**。
- 弃换组：`huanshe`（获得弃换次数）、`feishi`（主动弃换时反击）、`arrows_on_discard`（持续弃换追击）、`jiecang`（职业资源技能）。
- 连段组：`liandao`（双击）、`gonglian`（连段加成）、`lianhua`（额外抽牌）、`fleeting_blade`（临时快速攻击）。
- 三组共用战术策略机器人、相同初始 RNG 种子、相同卡组总数。**不能从该实验推论玩家在实际战役中有同等概率取得这些卡牌**，也不能把胜率差距直接归因于职业强度，因为四张特殊牌改变了起始构筑。

每个流派×难度单元汇报试验局数、通关数、抵达层数与完整 `CombatCounters`。观察弃换次数、三连触发、真正额外抽牌和护甲是否随构筑不同而改变，优先修复无法产生预期连招的机制和机器人策略缺陷，而非机械按照胜率增强某张牌。

## 验收和下一步

CI 对 macOS 与 Ubuntu 均执行严格 Clippy、单元测试、48个 Gherkin BDD 行为场景、存档中途恢复、1000局简单模拟、2200局平衡报告与495局孙尚香流派对照。所有报告 JSON 作为 Actions artifacts 保留，并分别要求**跨系统逐字节一致**；对样本数量、流派标签、分层覆盖和计数结构进行独立校验。

使用新 `CombatCounters` 前，已有存档计数默认为0。其语义为**从更新后开始累计**，不可追溯补填旧存档在此之前的战斗历史。除明确新增的终端诊断和模拟统计外，本轮不改变任何卡牌或职业数值；是否调整曹操需待真实输出/承伤与统御贡献数据验证后另行决定。
