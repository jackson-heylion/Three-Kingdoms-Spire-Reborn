# P1：15套构筑对指定Boss的固定战场配对实验（非成熟度验收）

2026-10-24 新增 `tests/boss_build_duels.rs`。此前 `boss_threshold_counterfactual.rs` 已验证司马懿、左慈的出牌阈值、特殊技实际结算与存档恢复；本轮进一步让 **15套预设构筑和原始起始牌组在同种子、同武将、同飞升、同Boss战场条件下打完真实战斗**，而不是只比较Boss预告。

实验固定：五职业各3套计划（`src/builds.rs`）、司马懿/左慈、飞升0/10、每单元2个固定种子。每个条件分别运行原始起始牌组和人工注入六张核心/辅助卡的预设牌组，共 **120组配对、240场完整Boss战斗**。两组都从第一层真实战斗进入，再把敌人替换为单体120生命Boss，初始意图为8伤害攻击；双方均使用确定性的“首张可出牌”机器人，单回合最多打36张牌，最多800个动作，不能结束则测试失败。

每场通过真实 `Game::apply(Action)` 结算至胜利（离开战斗进入奖励）或战败，收集：战斗胜负、从 `DamageReceived` 事件累计的英雄承伤、Boss是否进入二阶段、Boss特殊技能事件数、总动作数；期间和终局验证V2快照可保存/恢复。测试结束输出 `BOSS_DUEL_FIXTURE` 汇总，**通过测试只说明这些合成场景可以完整执行，不证明任何构筑优于基线**。统计指标必须以实际CI日志为准，不能将代码内计数器冒充实验结果。

## 可复验命令

```bash
cargo test --test boss_build_duels -- --nocapture
```

## 明确边界

- 构筑牌由测试直接替换起始牌，不经过正常奖励、商店、稀有度和获取概率；故不代表自然成型率。
- Boss被人工放在第一层且固定为120生命、单体开场，既不是三幕实际Boss战，也不覆盖召唤援军的全部排列；其他资源、地图、敌人位置也未作为自然随机变量。
- 双方共用同种子，但打牌差异会使后续RNG调用分叉；这是“相同初始随机种子”的配对，不是每回合完全同步的反事实随机数控制。
- “首张可出牌”机器人只是机械基线，不是多策略、人类水平或最优战术；每单元仅2种子，不能估算稳定胜率或统计显著性。生命损失按实际 `DamageReceived` 审计事件累计，非净生命变化。
- 测试禁用人工注入战斗的 `action_history`，不宣称这些合成状态可由初始种子重建；现有完整事件源重建仍未验收。
- 真人试玩、120回异本史料校勘、完整国际化、全部卡牌/敌军行为树和正式1.0仍未验收。
