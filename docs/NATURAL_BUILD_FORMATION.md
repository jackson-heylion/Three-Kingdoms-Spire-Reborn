# 五职业15套构筑：真实奖励获取率探索，不等于成熟流派验收

新增 `cargo run --release --bin tks-sim -- --natural-builds 1 report.json`。脚本在原有 `src/bin/tks-sim.rs` 中**复用真正的 Game::apply** 和同一个战斗 `tactical` 机器人；不对初始牌组手动塞入任何构筑卡、不改变常规掉率。每套从标准十张开局，在真实奖励界面优先拿**尚未拥有**的4张关键牌或2张支援牌，若当次没有符合条件的牌则回退原 tactical 选择。怪物、路线、阶段、奖励、金钱和卡池都走现有正式规则。

## 数据记录口径

- 15个构筑 `BuildPlan` × 11档飞升（0–10）× 每档 **1个固定种子** × 基线/定向挑牌2策略 = **165对、330局正常起始牌游戏**。CI 取单种子属于跨平台确定性**冒烟基线**，不是可以检出胜率差异的统计实验。
- 同一格基线与构筑偏好共用初始种子、武将、飞升和 tactical 战斗机器人；之后选牌不同会影响 RNG 消耗和遭遇路径，所以配对不是“相同敌人和手牌的精确反事实”，不能将相差胜局直接解读为卡牌强度。
- 每次运行记录 `baseline_wins` / `focused_wins`、到达楼层、`reward_screens`、`focus_offer_screens`、`focus_picks`、终局**实际持有**的关键/支援牌唯一ID数、是否集齐4关键或2支援。关注`完整关键牌成型/有多少次真正提供该构筑奖励/实际拾取`，避免“凑了4牌却没出现在随机奖励中”的假成型率。
- 因为仅统计最终牌组，途中曾拿到、又被删牌的情况不会计入`complete_core`；只给出最终成型状态。AI 依旧用当前商店策略且不会刻意买全部构筑卡，不等同最优人类运营。
- GitHub Actions macOS 14/Ubuntu 完整运行，校验每个 `id,ascension` 唯一、样本账、`focus_picks <= focus_offer_screens <= reward_screens`，并要求输出 JSON 跨平台**字节级一致**，制品放进原 `tks-balance-{os}` 压缩包。

## 与上一轮“夹具流派”研究的区别

| 数据 | 起始牌组 | 卡牌取得路径 | 可说明什么 | 不可说明什么 |
| --- | --- | --- | --- | --- |
| `--build-archetypes 2` | 把基础攻防牌强行替换成4核心+2支援（组合按原实现） | 无真实获取 | 理想情况下牌组能够打出什么结果 | 卡池自然成型概率 |
| `--natural-builds 1` | 标准十张原始牌 | 实际战后奖励，偏好构筑关键与支援卡 | 奖励牌能否取得、核心最终拥有数与目标策略的初步表现 | 单种子下统计显著胜率、对Boss克制 |
| `--natural-drafting 15` | 标准十张原始牌 | 自然奖励，设定孙尚香弃换/连段Doctrine | 孙尚香两类经营的495局配对探索 | 另外4职业的15构筑 |

**成熟构筑的剩余验收**：对每套追加足量种子、0–10飞升分层、前期成型楼层、成功/失败完整时间线、逐Boss遭遇/击败的分母（非只数最后死于谁）、多策略机器人与真人回合体验。依据事先确定的效应量和可靠度给置信区间；若多套负面或无差异则需要改牌池/数值后重新跑，不应拿最有利种子宣告平衡。当前仍不取消 `docs/P1_ACCEPTANCE.md` 的“部分”，不发布 1.0。
