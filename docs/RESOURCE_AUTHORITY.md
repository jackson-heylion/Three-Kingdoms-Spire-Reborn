# P1 持久资源权威事件（2026-10-24）

本增量从单纯战斗统计投影向**部分权威状态重建**推进。新增独立于 `RunEvent` 的 `ResourceEvent`，新战役从修订号0写入 `Started {hp,max_hp,gold}`，每个成功 `Game::apply` 原子附加一条 `Changed {revision,hp_delta,max_hp_delta,gold_delta}`。包括资源不变的成功动作（零增量），因此可检测动作边界缺失与重复。非法动作仍由现有候选态事务拒绝，不留下资源事件。

`resource_events::project()` 只读取该日志，按修订号连续、i32安全加法及资源边界规则恢复体力、最大体力和金币；`Game::audit_resources()` 对比恢复结果与当前快照、修订号。支持V2 JSON往返、独立于动作历史/RNG的资源恢复；旧V2缺少字段则保留 `None`，不伪造起始事件，审计明确拒绝，正常游戏与旧动作重放仍兼容。

**边界**：这是在已提交动作边界记录的三个持久资源，不是所有中间伤害/治疗事件，也不重建战斗军令、牌堆、敌军、地图、监听器、RNG或完整Game。日志与快照均可被同一攻击者篡改，不是密码学可信事件链。当前审计是显式只读API，旧档与直接手工修改的测试态不能据此宣称已通过；未把它升级为默认存档拒绝条件。每次成功动作均有一条事件，故记录长度与动作日志同阶。

复验：`cargo test --test resource_authority`，`cargo test --lib`；最终提交的macOS/Linux Rust测试、Clippy、Release与确定性CI全部成功前不得合并。真人试玩、全120回异本史料审校、15套成熟构筑及国际化继续未验收，不发布1.0。

## 2026-10-24 增量资源归约与检查点

新增 `ResourceProjector::push()`：逐条消费持久资源事件，只保留当前 `Resources` 与修订号；拒绝缺失初始事件、重复开始、跳号、重号、溢出及非法资源状态。所有校验先在候选态完成，失败不推进游标、不改变已提交状态。批量 `project()` 复用同一归约器，避免两套规则漂移。

`checkpoint()` 导出版本号1、当前资源和修订号；`resume()` 校验版本及资源边界，从下一修订号继续处理。JSON支持序列化往返，拒绝未知字段。**检查点不是完整事件日志，也不能验证被丢弃的历史前缀；没有密码学签名，不能抵御同时伪造检查点和后续事件的攻击。** 旧V2存档没有权威资源历史时仍不得伪造恢复证据。此增量不恢复战斗军令、牌堆、敌军意图、监听器或RNG，也不改变原有游戏数值、存档版本和正式P1未验收状态。

回归：`cargo test --test resource_authority`；最终以本PR最新SHA的macOS/Linux CI为准。
