## 本轮新增的关键鲁棒性边界

1. 新开战役的成功 `Game::apply(Action)` 记录完整动作；无效动作全回滚、没有日志污染。`Game::verify_action_replay()` 由种子/武将/模式/Run ID 重演，并精确比较JSON快照。不等同完整事件流重建；旧V2存档缺历史仍可读但不能声称已重放验证。
2. 本地终端版所有原子写入更新 `.bak`。主存档不合法但 `.bak` 可读时，损坏文件被改为 `.corrupt`，正常备份恢复为主存档；备份也损坏则拒绝假成功。
3. 玩家在 `tks --tui` 的互动上下键只选择菜单动作；输入 `:` 可进入原命令系统，复杂指定检索仍可以用 `play N TARGET SELECTION`，不复制另一套战斗规则。
4. 复杂资源组合矩阵以真实规则 `Game::apply` 和 `Game::to_json/from_json` 测试，覆盖行动拒绝的原子性、事件严格递增，以及单局升维/回放；它不代表已经测试所有持续军略的可能堆叠。

## 使用与复验

```bash
cargo run --release --bin tks -- --tui
cargo run --release --bin tks -- --plain
# 进入战役后：
# inventory / codex / achievements / history / verify / map
cargo test --all-targets
cargo run --release --bin tks-sim -- 1000
```

### 2026-10-19 P1 本地战役单写者保护（待 PR CI 验证）

采用 Rust 1.99.1 标准库文件锁，CLI/TUI 在读取任何存档、设置和战功簿前于同一存档目录上获得进程级独占锁，直到退出才释放。第二个终端进程在锁持有期间不可加入，也不会写入自己的进度；退出后同一存档目录可重进且保留原战役，残留 `.tks.lock` 文件不代表被占用。含 Rust 单元、严格 BDD、macOS/Linux CLI 真进程对抗测试。**该改进只解决本地协作锁机制下的覆盖风险**；不能替代 `fsync` 与断电日志、跨机器/网络存储互斥、真人试玩、全部内容/国际化/平衡验收或 P1 完成。

## 2026-10-19 P1 单文件存档与备份崩溃一致性（本 PR 待 macOS/Linux CI）

- 原 CLI 写盘代码直接复制旧主文件到 .bak（可能在复制中断时留下半个备份），也未同步临时文件。现迁移到 src/persistence.rs：独占创建同目录临时文件，write_all + sync_all 后 rename；旧版本备份亦采用临时文件完整写入与 rename，Unix 平台同步父目录。
- 新主版本写入前先稳定落盘上一版本备份。备份旋转失败则主文件不变并清理本轮临时文件。坏档恢复复用已由 Game::from_json 成功解析的备份原文字节，在隔离 .corrupt 后原子恢复主文件，不以坏档覆盖有效 .bak。
- 新增 3 条 Rust 单测（多代主档/备份、不可替换备份失败、恢复保留备份）、3 条严格 Gherkin BDD，以及 macOS/Linux GitHub Actions 真实 CLI 恢复进程验证。需等 PR 双平台 CI 完成后才算机器验证通过。
- 限制：仅覆盖遵守单写者锁约定的**单文件本地 POSIX 写入原子性与同步**；三个 JSON 文件之间尚非跨文件事务，不能承诺断电后所有磁盘控制器缓存、网络盘、外部非合作写入安全，也不保证 save 失败后内存行动自动回滚。真人终端测试、120回正文审校、完整国际化和全部职业/事件栈等 P1 阻断继续未验收，不得发布正式 1.0。

## 2026-10-19 P1 自动存档失败时拒绝提交战役动作（本 PR 待 CI）

- 发现终端命令路径原先先对内存中的 `Game` 执行 `apply`，再写入 `save.json`。如果磁盘写入失败，命令虽然报错，但修订号、RNG、战斗状态与动作日志已在内存中推进；重试相同指令可能重复行动。
